Context Switch
Dec 24, 2024

為什麼會需要 Context Switch

當我們的 Process 因為一些特定原因中斷時，需要將現有的運行狀態儲存起來，以便後續解決中斷後回到原本的 Process 狀態繼續執行。

當發生 Context Switch 時，CPU 會做什麼

  1. 保存當前程序的上下文，並將當前程序的資料存入 PCB (Process Control Block) 中。
  2. PCB 存入的資料包含:
    • 程序 ID (PID)
    • 程序優先級 (Priority)
    • 處理器使用時間
    • 記憶體分配 (包含地址範圍、共享內存、堆、全局變數)
    • 打開的文件描述符表 (File Descriptor Table)
    • 訊號處理 (signal handler) 資訊
    • Thread 的列表或索引
    • 指向Thread (Thread) 的 TCB 表 (如果有的話)

PCB 的結構

以下是 PCB 通常包含的詳細資訊：

1. 程序標識資訊

  • 程序 ID（Process ID, PID）：程序的唯一標識。
  • 父程序 ID（Parent Process ID, PPID）：創建該程序的父程序的 ID。
  • 用戶 ID（User ID, UID）與群組 ID（Group ID, GID）：程序所有者的身份資訊。

2. 程序狀態資訊

  • 程序狀態：如正在執行（Running）、就緒（Ready）、等待（Waiting）等。
  • 程序計數器（Program Counter, PC）：記錄程序的下一條指令地址。
  • 寄存器內容：保存程序暫停時處理器的寄存器狀態。

3. 記憶體管理資訊

  • 程序代碼段位置：代碼段的起始地址與大小。
  • Stack 位置：Stack 區域的起始地址與大小。
  • Heap 資訊：動態分配的記憶體區域的地址範圍。
  • 頁表或段表：程序的虛擬記憶體與實體記憶體的映射。

4. CPU 調度資訊

  • 程序優先級（Priority）：程序的優先執行順序。
  • CPU 時間片（Time Slice）：分配給程序的 CPU 時間。
  • 調度隊列指標：程序在調度隊列中的位置。
  • 執行時間：程序執行所需的時間資訊。

5. I/O 資源資訊

  • 打開的文件描述符表：列出程序當前打開的文件或設備。
  • I/O 緩衝區資訊：I/O 操作使用的緩衝區。
  • 設備分配資訊：程序占用的硬體設備（如硬碟、網卡等）。

6. 程序間通訊（Inter-Process Communication，IPC）資訊

  • 訊號處理表：記錄程序可以接收和處理的訊號類型。
  • 消息隊列：與其他程序的消息傳遞機制。
  • 共享記憶體段：程序間共享記憶體的地址範圍。

7. Thread 資訊（如果是多 Thread 程序）

  • Thread 列表或指針：指向該程序中所有 Thread Control Block（TCB）。
  • Thread 同步資訊：如鎖（mutex）、信號量（semaphore）等。

8. 額外資訊（可選）

  • 程序建立時間：程序被創建的時間戳。
  • 系統資源使用記錄：CPU 時間、記憶體使用量、I/O 次數等。
  • 安全資訊：訪問控制列表（Access Control List, ACL）、安全令牌等。
