STA: Static Timing Analysis
Dec 21, 2024

碩班研究時期曾經有協助學長處理關於 Gate-Level Netlist 的資料，但當時的資料都是已經經過 IC Compiler 的純文本，其中每筆資料的單位為 Path (PI/FF -> PO/FF)，其中的特徵大致包含 Path 中最小/平均/最大的 Fan-in/Fan-out/Power/Area 等，以及時序資料。當時其實不清楚這些資料是怎麼產出的，只知道與 STA 有關，趁此機會搞清楚 STA 到底在做甚麼。

STA 的核心概念

  1. 靜態分析
    • STA 不需要輸入測試向量，而是基於電路結構和時序約束來模擬所有可能的訊號傳輸路徑。
    • 檢查電路是在所有的訊號條件下滿足時序約束 (如 SDC: Synopsys Design Constrains)。
  2. 關鍵路徑
    • 檢查電路中訊號傳輸延遲最長的路徑，該路徑往往決定該電路最大的運行速度。
  3. 時序約束
    • 定義訊號在電路中傳播所需要滿足的條件，主要分為兩種:
      • Setup Time (建立時間)
      • Hold Time (保持時間)
  4. 主要分析對象
    • 主要分為四種:
      1. Flip-Flop to Flip-Flop
      2. Flip-Flop to Primary Output
      3. Primary Input to Primary Output
      4. Primary Input to Primary Output

STA 的主要目標

  1. 確保電路的功能
    • 驗證訊號是否能夠在指定的 clock 內正確傳播且穩定的到達輸出。
  2. 檢測時序問題
    • Setup Violation: 訊號無法再需要使用的時候底達元件。
    • Hold Violation: 訊號無法維持到需要使用的時候。
  3. 性能優化
    • 提供路徑延遲報告，幫助設計者優化晶片性能。

STA 的基本流程

  1. 輸入電路
    • 輸入 Gate-Level Netlist
    • 包括所有 Gate 之間的連接關係。
  2. 時序約束檔案 (SDC)
    • 定義電路的時序條件，如:
      • 時鐘週期 (Clock Period)
      • 訊號到達時間 (Arrival Time)
      • 輸出要求時間 (Required Time)
  3. 時序分析
    • STA 工具會計算所有路徑的訊號傳播延遲。
    • 驗證設計是否都符合 SDC。
  4. 報告生成
    • 生成關鍵路徑報告，以及可能的時序違規 (Violation)。

STA 在 IC 設計中的階段

前端設計階段

  • 執行階段: 在 RTL 設計完成後，經過邏輯合成 (Synthsis) 生成 Gate-Level Netlist 時。
  • 目的
    • 驗證是否符合 SDC 規範 (Setup time 及 Hold time)。
    • 確保 Synthesis Tool 產生的電路能在指定的 Clock Period 下運作。
  • 輸入
    • Gate-Level Netlist
    • SDC
  • 工具
    • Synopsys PrimeTime、Cadence Tempus 等。
      後端設計階段
  • 執行階段
    • 標準單元放置後 (Placement)
    • 時脈樹生成後 (Clock Tree Synthesis)
    • 佈線後 (Routing)
  • 目的
    • 驗證實際物理設計滿足時序需求。
    • 確保實際的佈局設計 (包含導線延遲和負載)不會導致時序違規。
  • 工具
    • Cadence Innovus、Synopsys ICC2 等工具內建的 STA 模組，或與專用的 STA 工具配合使用。
      設計完成階段 (Tape-Out 前最終確認)
  • 執行階段: 物理設計完成後 (GDSII 生成之前)
  • 目的
    • 確認所有 Violation 都解決。
    • 檢查邏輯設計與物理設計的一致性。

問題

  • 一般 SDC 檔案是上游還是下游提供
  • 為何 STA 分析對象是這些
  • FLip-Flop
  • CTS 跟 routing 的差別
