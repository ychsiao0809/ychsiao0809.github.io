STA: Static Timing Analysis
Dec 21, 2024

碩班研究時期曾經有協助學長處理關於 Gate-Level Netlist 的資料，但當時的資料都是已經經過 IC Compiler 的純文本，其中每筆資料的單位為 Path (PI/FF -> PO/FF)，其中的特徵大致包含 Path 中最小/平均/最大的 Fan-in/Fan-out/Power/Area 等，以及時序資料。當時其實不清楚這些資料是怎麼產出的，只知道與 STA 有關，趁此機會搞清楚 STA 到底在做甚麼。

STA 的主要目標

  1. 確保電路的功能
    • 驗證訊號是否能夠在指定的 clock 內正確傳播且穩定的到達輸出。
  2. 檢測時序問題
    • Setup Violation: 訊號無法再需要使用的時候底達元件。
    • Hold Violation: 訊號無法維持到需要使用的時候。
  3. 性能優化
    • 提供路徑延遲報告，幫助設計者優化晶片性能。

STA 的核心概念

1. 靜態分析 (Static Analysis)

  • STA 不需要輸入測試向量，而是基於電路結構和時序約束來模擬所有可能的訊號傳輸路徑。
  • 檢查電路是在所有的訊號條件下滿足時序約束 (如 SDC: Synopsys Design Constrains)。

2. 關鍵路徑 (Critical Path)

  • 檢查電路中訊號傳輸延遲最長的路徑，該路徑往往決定該電路最大的運行速度。

3. 時序約束 (Time Constrain)

  • 定義訊號在電路中傳播所需要滿足的條件，主要分為兩種:
    • Setup Time (建立時間)
    • Hold Time (保持時間)

4. 主要分析對象

1. Flip-Flop to Flip-Flop
2. Flip-Flop to Primary Output
3. Primary Input to Primary Output
4. Primary Input to Primary Output

STA 的基本流程

  1. 輸入電路
    • 輸入 Gate-Level Netlist
    • 包括所有 Gate 之間的連接關係。
  2. 時序約束檔案 (SDC)
    • 定義電路的時序條件，如:
      • 時鐘週期 (Clock Period)
      • 訊號到達時間 (Arrival Time)
      • 輸出要求時間 (Required Time)
  3. 時序分析
    • STA 工具會計算所有路徑的訊號傳播延遲。
    • 驗證設計是否都符合 SDC。
  4. 報告生成
    • 生成關鍵路徑報告，以及可能的時序違規 (Violation)。

IC 設計中不同的 STA 階段

階段 目標 輸入資料 分析重點 分析工具
Netlist STA (前端) 確保綜合後的邏輯設計滿足時序需求。 - Netlist after synthesis
- SDC 時序約束
- Cell Library (.lib)
- Wireload Model
- PVT(Process、Voltage、Temperature) Corner
- Clock Uncertainty (Skew or Jitter)		 - Setup/Hold 驗證
- 關鍵路徑分析
- 多時鐘域交互 (CDC) 驗證
- False Path & Multi-cycle Path 檢查		 Synopsys PrimeTime、Cadence Tempus
Placement STA (後端) 驗證元件放置後的邏輯結構時序是否受到影響。 - Netlist after synthesis
- 初步放置結果（元件物理位置）
- SDC 時序約束
- Cell Library (.lib)
- 初步 Clock Tree 模型
- 初步 Wireload 或 RC 模型		 - 初步實體設計的時序驗證
- 關鍵路徑是否受放置影響
- 時鐘樹初步偏移檢查
- 緩衝器插入對時序的影響		 Cadence Innovus、Synopsys ICC2
Post-Route STA (後端) 精確分析考慮實際 RC 延遲的電路時序。 - 路由完成的 Netlist
- 精確的 RC 模型 (SPEF)
- 完整的時鐘樹實現 (CTS 結果)
- Updated SDC 約束
- PVT 角落條件
- Clock Uncertainty		 - 實際路由對時序的影響
- RC 提取對 Setup/Hold 的影響
- 高 RC 延遲路徑的調整
- 多角落/多模式分析		 Cadence Innovus、Synopsys ICC2
Sign-Off STA (後端) 確保設計在所有條件下滿足製造要求並通過驗證。 - 最終 Netlist
- 完整的 RC 提取模型 (SPEF)
- 製程角落庫 (.lib, OCV/Aging Effects)
- 最終 SDC 約束
- 不同角落條件（SS, TT, FF 等）		 - Setup/Hold 驗證的最終檢查
- 多角落（PVT）、多模式的全覆蓋分析
- 設計是否滿足所有時序要求
- 設計是否可以投入製造		 Cadence Innovus、Synopsys ICC2
